# 인수인계 (elMotion)

긴 대화는 매 요청마다 앞의 내용을 다시 읽어 사용량이 커진다. 배포 3번마다 상태를 파일 하나로 정리하고 대화를 가볍게 만든다.

## 언제
- 이 대화에서 '배포해'로 배포한 횟수가 3, 6, 9…번째가 된 직후 (배포 결과 답장 끝에서 바로 진행).
- 사용자가 "인수인계", "새 대화", "압축"이라고 할 때.

## 1. handoff.md 갱신 (40줄 안쪽)
`.claude/handoff.md`를 덮어쓴다. 항목만 짧게:
- 저장소·아티팩트 URL·배포 순서 (바뀐 게 없으면 그대로 둠)
- 배포본: 커밋 해시, APP_VERSION, CACHE, EVAL_VER, 아티팩트 버전
- 항상 지킬 규칙 (사용자가 새로 정한 규칙은 여기에 추가)
- 확정된 기준·수치 (경사형 기준 등)
- 최근 한 일 (최근 배포 3~5개만, 한 줄씩. 오래된 건 지운다)
- 남은 일 (끝난 건 지운다)
- 작업 팁 (앱 전역 객체, 미리보기 방법 등)

대화 내용·과정·시도 실패 이야기는 넣지 않는다. 결과와 다음에 필요한 사실만.
배포 직후라면 handoff.md 변경은 다음 배포 커밋에 함께 넣는다 (규칙: 푸시는 '배포해' 때만). 사용자가 바로 넘기길 원하면 "handoff.md만 푸시할까요?"라고 묻는다.

## 2. 넘기는 방법을 묻는다 (한 번만, 짧게)
"배포 3번이 쌓였어요. 이어 가는 방법을 골라 주세요:
 A) 새 세션 만들기 — 제가 만들고 링크를 드려요 (가장 가벼움)
 B) 이 세션 압축 — 아래 문장을 입력해 주세요"

### A) 새 세션
- handoff.md가 원격 main에 있어야 한다 (없으면 1단계 푸시를 먼저 확인).
- `create_session`: source_url `https://github.com/sphw7703/elMotion`, title "elMotion 이어서 (버전)",
  prompt: "elMotion 작업 이어서. 먼저 add_repo(sphw7703/elMotion, access: push)로 저장소를 붙이고, `.claude/handoff.md`를 읽은 뒤 lean-coding-session 규칙대로 해줘. 읽고 나서 남은 일 목록만 짧게 보여 주고 지시를 기다려."
- 만든 세션 링크를 알려 주고 이 세션 작업은 멈춘다.

### B) 같은 세션 압축
`/compact`는 사용자만 입력할 수 있다. 이 문장을 그대로 복사해 쓰게 준다:
```
/compact .claude/handoff.md 내용과 지금 진행 중인 일만 남기고 나머지 대화는 버려줘
```
압축 뒤에는 `.claude/handoff.md`만 읽고 이어 간다 (예전 파일 내용 다시 읽지 않음).

## 새 세션에서 이어받을 때
- 저장소를 붙이고 클론한 뒤 `.claude/handoff.md` 하나만 읽는다. 코드 전체를 미리 읽지 않는다.
- 남은 일 목록만 보여 주고 지시를 기다린다.
